## Notes & Design Choices
- Centralized error handling: `@handle_errors` ensures consistent return shape and logging, reducing duplicated try/except blocks.
- Parameterized queries: used `?` as a placeholder for queries (safe against SQL injection).
- Dependency injection points:
  - DB: `execute_fn` in `DatabaseToolRefactored` allows tests to inject a deterministic result.
  - API: `_request_fn` in `APIToolRefactored` enables injecting fake responses in tests.
- I preserved backward-compatible public method names (`query_users`, `fetch_weather`, etc.), so the existing API stays the same while internals are refactored.
